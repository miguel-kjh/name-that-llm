# Memoria del proyecto

Correcciones y lecciones que da el usuario y que deben sobrevivir entre sesiones.

## Formato de cada entrada

Cada entrada es un archivo propio en `kb/memory/`, con un nombre corto en kebab-case
(por ejemplo, `no-random-splits.md`), y tiene tres partes:

```markdown
# <título corto>

**Regla:** qué hay que hacer o evitar.

**Por qué:** el motivo, o el incidente que la originó.

**Cómo aplicarla:** cuándo se aplica y qué hacer en concreto.
```

## Cómo mantener el índice

- Una línea por entrada: `- [Título](archivo.md) — resumen en una frase`.
- Antes de crear una entrada, comprueba si ya hay una que cubra lo mismo y actualízala.
- Si una entrada deja de ser cierta, bórrala junto con su línea del índice.
